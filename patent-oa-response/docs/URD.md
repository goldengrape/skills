# URD：专利 OA 答复 OKF 技能流程库

## 1. 项目定位

本 OKF bundle 用于辅助处理专利审查意见通知书（OA）答复。它的目标不是替代专利代理师或律师，而是把案卷读取、事实核对、审查意见拆解、答复策略生成、审查员模拟、风险评估和最终草稿整理成可复核的单向流程。

## 2. 使用者和角色

| ID | 角色 | 需要完成的事 |
|---|---|---|
| URD-ROLE-001 | 专利代理师 / 律师 | 快速核对案卷、识别可争辩点、形成可提交前核对的答复草稿。 |
| URD-ROLE-002 | 申请人 / 发明人 | 理解答复方案、保护范围损失、授权风险和可让步事项。 |
| URD-ROLE-003 | AI 执行代理 | 按固定流程调用子 skill，区分事实、判断和策略，不跳步、不自我循环。 |

## 3. 目标

| ID | 目标 | 成功标准 |
|---|---|---|
| URD-GOAL-001 | 建立可靠事实底稿 | 每个关键事实均能追溯到权利要求、说明书、附图、审查意见或对比文件。 |
| URD-GOAL-002 | 形成可比较的答复方案 | 至少能比较当前方案、授权优先方案和范围平衡方案。 |
| URD-GOAL-003 | 降低错误乐观和循环修订 | 胜率只由独立评估步骤给出，修订步骤不得自行上调胜率。 |
| URD-GOAL-004 | 输出可人工复核的最终文本 | 最终文本包含修改说明、创造性论证、风险提示和提交前核对清单。 |
| URD-GOAL-005 | 在最终输出前阻断高风险错误 | 通过领域 hard gate 检查未读文件、无支持修改、遗漏拒绝理由、虚构引用、自评循环、法域错配和最终稿新增论点。 |

## 4. 范围

### 4.1 当前范围

| ID | 范围项 |
|---|---|
| URD-SCOPE-001 | 中国专利审查意见答复的一般分析流程。 |
| URD-SCOPE-002 | 原申请、审查意见、对比文件、权利要求修改稿和已有答复稿的读取与分析。 |
| URD-SCOPE-003 | 新颖性、创造性、清楚性、支持和修改超范围风险的辅助判断。 |
| URD-SCOPE-004 | 权利要求修改建议、意见陈述草稿、电话沟通提纲和最终建议。 |
| URD-SCOPE-005 | 领域质量守门规则、领域评分标准和 dry-run 测试 prompt。 |

### 4.2 不在当前范围

| ID | 排除项 |
|---|---|
| URD-OOS-001 | 不承诺授权结果，不输出“必然授权”判断。 |
| URD-OOS-002 | 不替代执业专利代理师、律师或客户最终策略决定。 |
| URD-OOS-003 | 不自动提交文件，不处理官方电子申请系统的登录和递交。 |
| URD-OOS-004 | 不在缺少关键文件时给出确定性法律结论。 |

## 5. 功能需求

| ID | 功能需求 | 验收标准 |
|---|---|---|
| URD-REQ-001 | 接收并检查案卷文件完整性。 | 输出文件清单、缺失文件、可读性、继续分析限制。 |
| URD-REQ-002 | 建立原申请事实底稿。 | 输出原发明构思、权利要求结构、说明书支持点、可修改特征池。 |
| URD-REQ-003 | 拆解审查意见。 | 输出每个拒绝理由、审查员认定的区别特征、技术问题、组合路径和公知常识认定。 |
| URD-REQ-004 | 制作权利要求要素与对比文件映射表。 | 每个独立权利要求要素均映射到审查意见、主对比文件、组合文件和其他引证。 |
| URD-REQ-005 | 形成当前答复候选。 | 有答复稿时输出审稿结论；无答复稿时输出初版答复候选。两者都必须使用同一候选输出结构。 |
| URD-REQ-006 | 模拟审查员反驳。 | 输出下一份审查意见雏形，包括可能接受内容、可能维持缺陷、组合路径和逐条反驳。 |
| URD-REQ-007 | 独立评估授权概率区间和风险。 | 只给区间，不给单点数字；同时说明失败路径、保护范围损失、复审价值和授权后稳定性。 |
| URD-REQ-008 | 生成 A/B 修订方案。 | A/B 必须在权利要求限定或法律策略上有实质差异，不得只是措辞不同。 |
| URD-REQ-009 | 对 A/B 进行二次模拟、二次评估并选择方案。 | 二次胜率必须来自模拟与评估步骤，不得由修订步骤自行给出。 |
| URD-REQ-010 | 执行领域质量守门。 | 在当前候选、胜率评估、A/B 选择和最终文本前检查 hard gates；触发时回到对应上游步骤。 |
| URD-REQ-011 | 生成最终答复草稿。 | 输出修改说明、意见陈述、从属项/方法项处理、领域质量守门结果、电话沟通建议和提交前人工核对清单。 |

## 6. 约束

| ID | 约束 |
|---|---|
| URD-CON-001 | 事实、判断、策略必须分开标注。 |
| URD-CON-002 | 不得只根据审查意见转述对比文件；对比文件未读时必须标注限制。 |
| URD-CON-003 | 胜率评估只能由专门评估步骤输出；审稿、起草和修订步骤只能提供风险线索。 |
| URD-CON-004 | 默认最多两轮“模拟 → 评估 → 修订”循环；继续迭代必须有新增事实、特征、证据或用户策略变化。 |
| URD-CON-005 | 最终输出必须提示人工核对，不可直接视为可提交法律意见。 |
| URD-CON-006 | OKF 文件应保持小型、可组合、可预测；不得用重复模板掩盖职责重叠。 |
| URD-CON-007 | 法域和程序阶段未确认时，不得输出具体程序路径作为最终建议。 |
| URD-CON-008 | 最终答复草稿不得新增未经过模拟、评估和质量守门的核心论点或权利要求限定。 |

## 7. 假设和开放问题

| ID | 类型 | 内容 |
|---|---|---|
| URD-ASM-001 | 假设 | 用户能够提供审查意见、当前权利要求、说明书和主要对比文件。 |
| URD-ASM-002 | 假设 | bundle 以 Markdown + YAML frontmatter 的 OKF 形式交付。 |
| URD-Q-001 | 开放问题 | 是否需要进一步区分中国、美国、欧洲等不同法域的完整 OA 答复流程。当前版本先增加法域确认和错配检查，默认仍按通用中国专利答复语境处理。 |
