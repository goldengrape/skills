# 目的

防止在缺少关键文件时过早给出确定性判断。特别是：OA 中被审查员用来支持“常规技术手段、公知常识、组合启示”的证据，必须被单独列为“审查员证据清单”。

# 步骤

1. 列出所有已收到文件。
2. 按类型归类：申请文件、审查意见、对比文件、修改稿、答复稿、其他证据。
3. 确认法域和程序阶段：例如中国实审 OA、美国 non-final/final OA、欧洲 communication；未确认时标注“法域未确认”。
4. 从 OA 中抽取审查员引用的全部证据，包括主对比文件、组合文件、补充引证文件、教科书、工具书、标准、公知常识证据。
5. 判断每份文件是否已提供、可读取、完整、是否为扫描件。
6. 列出缺失但重要的文件，并区分“申请人文件缺件”和“审查员证据缺件”。
7. 判断是否可以继续分析。

# 继续分析标准

至少需要：审查意见、当前权利要求、说明书、主对比文件。若缺少对比文件全文，可以先做初步分析，但必须标注“对比文件部分未核对”。

若 OA 中引用了补充引证文件、教科书、工具书或公知常识证据，但案卷未提供这些文件：

- 可以继续做 OA 拆解、已有答复稿审查和待补证据清单；
- 不得在最终答复草稿中确定性断言“该证据不能证明常规技术手段”；
- 最终输出必须降级为“审稿与修订建议”或“供代理人核对的草稿”；
- 需要在领域质量守门中触发 HG-01/HG-05，直到补齐并核对相关证据。

若法域未确认，可以继续做事实底稿和通用风险分析，但不得使用具体法条、官方程序路径或最终提交建议。

# 🔴 STOP / CHECKPOINT

出现以下任一情况时，停止生成“可提交最终稿”，只输出限制说明和下一步补证据建议：

1. 审查员用于关键拒绝理由的主对比文件或补充引证文件未提供；
2. 说明书或当前权利要求缺失，无法核对修改支持；
3. 法域或程序阶段未确认，但用户要求具体提交文本；
4. 前次答复被审查员逐条反驳，而前次答复全文未提供。


# 正文证据扫描

完成首页文件表抽取后，必须继续扫描 OA 正文。遇到 `CN`、`US`、`EP`、`WO` 等公开号，或“例如现有技术中……”后列举的文件，应加入审查员证据清单，即使首页写明“未引用新的对比文件”。

输出时将证据来源标成：

- 首页对比文件表；
- 正文补充引证；
- 公知常识 / 常规技术手段证据；
- 前次答复反驳依据。


# 复杂内容完整性检查

文件接收阶段必须检查是否存在公式、附图、表格、上下标或单位。若存在，应记录读取方式：

| 内容类型 | 出现位置 | 抽取是否完整 | 核对方式 | 限制 |
|---|---|---|---|---|
| 数学式/表格/附图 |  | 完整 / 丢失 / 待核对 | 原文件 / 渲染图 / 人工核对 |  |

抽取不完整时，不得对相关权利要求要素作确定性判断。
