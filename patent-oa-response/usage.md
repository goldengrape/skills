# 适用范围

这套 bundle 用于辅助处理专利审查意见答复，尤其适合以下场景：

- 已收到一通、二通或驳回前审查意见，需要分析授权路径；
- 已有代理人答复稿，需要复核其说服力和风险；
- 尚无答复稿，需要草拟权利要求修改方案和意见陈述；
- 希望通过“模拟审查员 → 胜率评估 → A/B 修订 → 再模拟”的方式提高答复质量。

它是通用流程，不绑定任何具体案号、技术领域或本次对话中的具体项目。

# 最小调用方式

把案卷文件放入同一会话或同一工作目录，然后向代理输入：

```text
请使用 /patent-oa-response 处理本案。目标：授权优先，同时尽量保留合理保护范围。
已提供文件包括：原申请文件、最近一次审查意见、对比文件、当前权利要求、已有答复稿。
```

如果没有已有答复稿，可以写：

```text
请使用 /patent-oa-response 处理本案。没有代理答复稿，请先完成案卷分析，再草拟初版答复候选和 A/B 修订方案。
```

# 输入文件建议

| 文件 | 是否必要 | 用途 |
|---|---:|---|
| 原权利要求书 | 必要 | 识别原保护范围和可修改空间 |
| 原说明书及附图 | 必要 | 查找修改依据和技术效果 |
| 审查意见通知书 | 必要 | 提取拒绝理由和审查员组合逻辑 |
| 对比文件全文 | 必要 | 做逐要素映射，避免只依赖审查员转述 |
| 修改对照页 | 可选 | 审查修改是否有效、是否超范围 |
| 已有答复稿 | 可选 | 进入审稿路径；没有则进入起草路径 |
| 客户策略偏好 | 建议 | 决定授权优先、范围优先或复审准备 |
| 法域和程序阶段 | 建议 | 决定中国、美国、欧洲或其他法域的分析口径 |

# 推荐执行顺序

1. 先读 [总控流程](skills/patent-oa-response.md)。
2. 按 [文件接收规则](playbooks/document-intake.md) 检查案卷完整性。
3. 用 [事实底稿 skill](skills/patent-file-reading.md) 建立原申请事实底稿。
4. 用 [审查意见拆解 skill](skills/patent-oa-analysis.md) 拆解拒绝理由和组合逻辑。
5. 用 [Claim Chart skill](skills/patent-claim-chart.md) 建立权利要求要素映射。
6. 有代理稿时调用 [答复稿审查 skill](skills/patent-response-review.md)；没有代理稿时调用 [答复起草 skill](skills/patent-draft-response.md)。
7. 用 [模拟审查员 skill](skills/patent-examiner-simulation.md) 进行强反驳。
8. 用 [胜率评估 skill](skills/patent-win-rate.md) 给出区间评估。
9. 用 [A/B 修订 skill](skills/patent-revision-variants.md) 生成两套方案。
10. 对 A/B 再模拟、再评估，最后选择提交方案。
11. 用 [最终答复 skill](skills/patent-final-response.md) 整理最终草稿。

# 关键规则

- 不得只摘要，要做权利要求要素映射。
- 不得只根据审查意见转述对比文件，必须直接阅读对比文件。
- OA 中的审查员补充引证文件、教科书、工具书或公知常识证据必须列入“审查员证据清单”。
- 审查员证据缺件时，不得输出可提交版本；只能输出审稿与修订建议或供代理人核对的草稿。
- 若 OA 已经反驳前次申请人论点，后续答复不得机械复用；必须删除、改写或补充新证据/新限定。
- 存在独立方法权利要求时，不得只依附装置权利要求结论，必须单独分析方法步骤和工艺分工。
- 胜率只给区间，不给单点数字。
- 胜率只能由胜率评估步骤输出。
- 最终文本前必须执行领域质量守门；触发 hard gate 时回到对应上游步骤修复。
- 法域未确认时，不得使用具体程序路径作为最终建议。
- A/B 方案必须是策略差异，不是措辞差异。
- A/B 方案本身不输出最终概率；必须经过二次模拟和二次评估。
- 迭代最多两轮；没有新增事实、可加入特征或新论证路径时，不得上调胜率。

# 输出物

真实 OA 场景中，优先输出“审稿报告 + 修订策略”。只有领域质量守门通过后，才生成最终答复文本。

完整运行后，应至少输出：

1. 案卷完整性检查表；
2. 原申请事实底稿；
3. 审查意见拆解；
4. 对比文件 claim chart；
5. 当前答复稿审查，或初版答复候选；
6. 模拟审查员意见；
7. 胜率评估；
8. A/B 修订方案；
9. A/B 二次模拟和二次胜率评估；
10. 推荐提交方案；
11. 领域质量守门结果；
12. 可选电话沟通提纲；
13. 最终答复草稿，或在 hard gate 触发时输出“审稿与修订建议”。

# 注意

这套流程用于辅助专利代理和申请人形成答复策略，不替代执业专利代理师或律师的专业判断。涉及提交前文本时，应由负责该案的代理人核对法律依据、修改支持、用语清楚性和客户商业保护目标。


## 后续 OA 通用强风险检查

遇到二通或更后续 OA 时，除常规流程外必须检查：

1. OA 正文是否存在首页未列出的补充引证；
2. 从属权利要求是否已有具体证据需要逐项回应；
3. 数学式、附图、表格、单位或关键参数是否被完整读取；
4. 当前答复是否复用前次已被审查员反驳的论点。

# 回归测试

每次修改 bundle 后，应按 `tests/regression-suite.md` 检查：JSON 可解析、Markdown 无断链、最终模板覆盖 HG-01 到 HG-13，并且不包含真实案号、客户名称、申请号、真实文件名、真实公开号或真实测试报告。

# 隐私要求

通用发布版不得包含真实案件材料。若团队需要使用真实案件做内部回归，应放在独立私有测试包中，并在打包前再次执行脱敏搜索。
