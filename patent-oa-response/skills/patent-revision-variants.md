# 作用

生成两组策略不同的答复修订方案，而不是两个措辞不同的版本。

本 skill 只生成方案，不给最终授权概率。A/B 的概率区间必须在二次模拟和二次评估后由 [patent-win-rate](patent-win-rate.md) 给出。

# 输入

- 当前答复候选；
- 模拟审查员意见；
- 胜率评估；
- 可修改特征池；
- claim chart；
- 客户策略偏好。

# A/B 方案定义

## A：授权优先方案

目标：最大化授权可能性。

特点：

- 收窄到说明书中支持最强、对比文件最难覆盖的实施例；
- 删除或下放容易被认定为常规的替代方案；
- 强化技术效果和整体组合关系；
- 接受一定保护范围损失。

## B：范围平衡方案

目标：在提高授权可能性的同时保留更多商业保护范围。

特点：

- 只加入必要限定；
- 保留部分替代方案或较宽表达；
- 强化意见陈述；
- 接受较高审查风险。

# 执行完整文本

当用户要求“分别执行 A/B”时，为每组输出：

1. 修改说明；
2. 权利要求修改建议；
3. 意见陈述主线；
4. 从属项答复；
5. 方法项答复；
6. 电话沟通问题；
7. 二次模拟需要重点测试的问题。

# 完成标准

A/B 必须在权利要求限定或法律策略上有实质差异。若两者只是表述不同，应合并为一个方案。

完成后必须交回总控流程，对 A/B 分别再次执行审查员模拟和胜率评估。


# 后续 OA 修订要求

第二次或更后续 OA 中，A/B 方案不得只是措辞变化。每个方案必须说明：

| 方案 | 新增事实基础 | 新增限定 | 新的实际解决技术问题 | 如何回应正文补充引证 | 如何处理从属项具体证据 |
|---|---|---|---|---|---|

没有新增事实基础、新限定或新技术问题的方案，只能标为“不推荐提交”。
