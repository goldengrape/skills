# 作用

把审查意见通知书拆成可核对的拒绝理由表。该 skill 只还原审查员的认定和逻辑，不直接生成修改方案，不评估授权概率。

# 输入

- 审查意见通知书；
- 原申请事实底稿；
- 当前权利要求；
- 对比文件清单；
- 审查员引用的公知常识、惯用手段或补充证据，如有；
- 前次答复或当前已有答复稿，如有。

# 步骤

## 1. 拒绝理由列表

按权利要求和法条列出每个拒绝理由。

| 权利要求 | 拒绝理由 | 主对比文件 | 组合文件 | 审查员结论 |
|---|---|---|---|---|

## 2. 审查员证据清单

把 OA 中所有被审查员引用的证据单独列出，不限于主对比文件。

| 证据 ID | 名称 / 公开号 | 审查员用途 | 是否已提供原文 | 是否已读取 | 未核对时的限制 |
|---|---|---|---:|---:|---|

若补充引证文件用于证明常规技术手段、公知常识或组合启示，但原文未提供，必须标记为“审查员证据缺件”。

## 3. 审查员创造性逻辑

对每个独立权利要求输出：

1. 最接近现有技术；
2. 审查员认定的区别特征；
3. 审查员认定的实际解决技术问题；
4. 技术启示来源；
5. 公知常识或惯用手段认定；
6. 审查员结论。

## 4. 已被审查员反驳的申请人论点

若 OA 对前次答复作出回应，输出：

| 原申请人论点 | 审查员反驳内容 | 反驳依据位置 | 后续是否可复用 | 处理要求 |
|---|---|---|---|---|
|  |  |  | 不可直接复用 / 可改写 / 可保留 |  |

后续是否可复用的判断只能基于：新增证据、新增权利要求限定、重新定义技术问题或审查员误读。没有这些基础时，标为“不可直接复用”。

## 5. 必须回应的问题

把审查意见转成答复必须回应的问题清单：

| 问题 ID | 来源 | 必须回应的问题 | 需要后续核对的文件 |
|---|---|---|---|

## 6. 不确定内容

列出需要在 claim chart 或事实底稿中继续核对的内容，例如：

- 对比文件未读取全文；
- 审查员补充引证文件未提供；
- 审查员引用段落不清楚；
- 审查员把多个特征合并认定；
- 公知常识缺少证据来源；
- 前次答复被反驳但前次答复全文缺失。

# 输出结构

```markdown
## 审查意见拆解

### 拒绝理由表

### 审查员证据清单

### 创造性逻辑

### 已被审查员反驳的申请人论点

### 公知常识和组合路径

### 必须回应的问题

### 需要进一步核对的内容
```

# 完成标准

必须覆盖审查意见中的每个拒绝理由。若某一拒绝理由缺少对比文件或补充引证文件全文支撑，必须标注“需要进一步核对”，不得假定审查员认定正确，也不得假定审查员认定错误。


# 正文证据扫描规则

拆解 OA 时，必须扫描正文中的公开号、公告号、论文、标准、教科书和工具书。首页“本通知书未引用新的对比文件”不代表正文没有补充引证。若正文使用其他文件证明“常规技术手段”“公知常识”或“常规排列方式”，必须列为“正文补充引证”。

输出时加入：

| 正文位置 | 证据 | 审查员用途 | 是否首页列明 | 是否已读取 | 若未回应的风险 |
|---|---|---|---:|---:|---|
