# 作用

读取原申请文件，建立后续 OA 拆解、claim chart、审稿、起草和评估都要使用的事实底稿。

本 skill 只处理“文件实际记载了什么”。它不得提前判断授权概率，也不得生成答复策略。审查意见拆解由 [patent-oa-analysis](patent-oa-analysis.md) 完成。

# 输入

- 原权利要求书；
- 说明书和附图；
- 当前权利要求书；
- 修改对照页，如有；
- 其他由用户提供、可作为事实来源的材料。

# 步骤

## 1. 文件清单

列出每份文件的名称、类型、页数或可读取范围、是否完整、是否为扫描件。

## 2. 原发明分析

输出：

- 原发明一句话概括；
- 技术领域；
- 背景问题；
- 独立权利要求结构；
- 从属权利要求层级；
- 说明书反复强调的技术效果；
- 可用于修改的具体结构、步骤、参数和效果。

## 3. 说明书支持点

建立“可加入特征池”：

| 可加入特征 | 说明书位置 | 对应附图 | 可解决的审查问题 | 风险 |
|---|---|---|---|---|

风险包括：超范围、不清楚、必要技术特征缺失、保护范围过窄。

## 4. 当前权利要求结构

如已提供当前权利要求或修改对照页，输出：

- 已修改的权利要求；
- 新增、删除或替换的技术特征；
- 每个新增特征的原文依据；
- 与说明书支持点的对应关系；
- 未找到支持位置的内容。

# 输出结构

```markdown
## 原申请事实底稿

### 文件清单

### 原发明概括

### 权利要求结构

### 说明书支持点

### 可加入特征池

### 当前权利要求变化，如有

### 未能读取或不确定的内容
```

# 完成标准

完成时必须提供：

1. 原发明构思；
2. 权利要求结构；
3. 说明书支持点；
4. 可修改特征池；
5. 当前权利要求变化，如有；
6. 未能读取或不确定的内容。

不得输出授权概率、答复策略或审查员可能接受程度。
