## 矩阵分类

- classification: decoupled
- reason: 流程本身有确定顺序；后续 FR 只依赖前序步骤的不可变产物或事件。最后一行是观察和恢复要求，不反向改变各业务模块。
- execution_order: DP1 → DP2；DP3 可与 DP2 独立准备；随后 DP4 → DP5 → DP6 → DP7；DP8 全程消费事件并协调顺序。

## 耦合修订记录

| 尝试 | 问题 | 修改 | 结果 |
| --- | --- | --- | --- |
| 1 | 单个“委派器”同时处理 ZIP、浏览器、状态和解压，设计矩阵稠密。 | 拆分本地确定性文件处理与浏览器副作用。 | 文件逻辑可以脱离浏览器测试。 |
| 2 | 每个模块直接修改 `state.json`，状态格式会影响所有模块。 | 各模块只返回不可变结果或事件，由 DP8 写入状态。 | 状态持久化不再进入业务模块。 |
| 3 | 回复判断、下载触发和文件发现混在浏览器适配层。 | 分出响应监测器和下载解析器。 | DOM 变化、下载目录变化和结果验证可分别处理。 |

## Accepted Coupling / 接受的耦合

没有接受的结构性耦合。矩阵中的非对角项均为任务顺序产生的数据依赖，接口和测试可以分别约束。

## 关键设计决定

| ID | 决定 | 依据 |
| --- | --- | --- |
| DEC-001 | 浏览器操作不写入 Python 自动化脚本，只通过 Codex Browser Skill 执行。 | URD-CON-001；登录会话已由内置浏览器验证。 |
| DEC-002 | ZIP、哈希、路径检查和状态转换使用确定性 Python 脚本。 | 这些步骤规则固定，错误代价高。 |
| DEC-003 | 实际 Skill 包不包含本设计文档；设计文档保留在开发项目。 | URD-CON-005 和 Skill Creator 精简原则。 |
| DEC-004 | 实时 ChatGPT Web 测试为显式启用的回归测试，不作为每次单元测试的前提。 | 网页状态和账号额度不稳定。 |
| DEC-006 | Codex 与 ChatGPT Web 只通过 ZIP 交换任务资料；可预览的单个文件不作为下载目标。 | 可预览附件点击后进入预览状态，预览界面不适合作为可靠下载路径。 |
