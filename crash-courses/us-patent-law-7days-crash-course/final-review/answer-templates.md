# Answer Templates

## Short answer: rule explanation

```text
This issue concerns [concept]. The basic rule is [rule]. The reason is [policy / doctrinal function]. In a simple fact pattern, I would check [conditions]. Therefore, the key distinction is [contrast].
```

## Issue spotting: patentability

```text
First, identify the claim and application posture. Then analyze §101, §102, §103, and §112 separately. Do not collapse eligibility, novelty, obviousness, and disclosure into one question. End by stating what additional facts would matter.
```

## Comparison answer

```text
A and B are related because [shared context]. They differ because A asks [question], while B asks [question]. A common mistake is [mistake]. In a fact pattern, I would look for [facts].
```

## Flawed-answer repair

```text
The answer reaches a plausible conclusion but uses the wrong route. It confuses [concept 1] with [concept 2]. A better route is to first ask [step], then [step], and only then reach a conclusion.
```

## Gate-selection opening

```text
The first issue is [gate]. I know this because the facts emphasize [trigger]. This gate asks [question]. I will not answer it with [adjacent gate] because [reason].
```

## §101 Alice/Mayo compact template

```text
The claim likely fits [statutory category]. The possible judicial exception is [abstract idea / law of nature / natural phenomenon]. The facts suggesting ordinary implementation are [facts]. The facts suggesting practical application or technical improvement are [facts]. Novelty and obviousness should be analyzed separately under §102 and §103.
```

## §103 compact template

```text
The PHOSITA is [field/time/skill]. The prior art teaches [A] and [B], while the claim adds [difference]. A reason to combine is [design need / market pressure / predictable result / known substitution], supported by [fact]. A counterargument is [teaching away / unpredictability / missing reason / secondary consideration].
```

## §112 broad-claim compact template

```text
The claim is broad because [scope]. Written description asks whether the specification shows possession of that scope as of filing. Enablement asks whether a PHOSITA can make and use the full scope without undue experimentation. The strongest facts are [support], while the weakest facts are [gap].
```
